# CNN 第三课：学习率、batch size 和 epoch

第二课已经让 SmallCNN 学会识别 MNIST。本课继续使用同一个网络，学习怎样解释训练设置和实验结果。

目标：能区分这三个设置，算出更新次数，并通过一次只改一个设置的实验观察训练变化。

## 1. 先把三个概念分开

```python
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)
train_loader = DataLoader(train_subset, batch_size=64, shuffle=True)
for epoch in range(3):
    train_one_epoch(...)
```

| 设置 | 控制什么 | 不能混淆的地方 |
|---|---|---|
| 学习率 `lr=0.001` | 优化器更新参数的幅度系数 | 不表示每次把每个权重都减去 0.001 |
| `batch_size=64` | 一次用最多 64 张图片计算梯度并更新参数 | 不是只用这 64 张图片完成整轮训练 |
| `epochs=3` | 把本次选用的完整训练集学习 3 遍 | 一轮通常包含很多次参数更新 |

在当前代码中，每个 batch 调用一次 `optimizer.step()`，所以一个 batch 对应一次更新。以后如果使用梯度累积，这个对应关系可以变化。

卷积核和全连接层的权重由训练学出来；学习率、batch size、epoch 是我们事先设置的**超参数**。

## 2. 学习率：每次更新的幅度系数

先用最简单的梯度下降公式建立直觉：

```text
新权重 = 旧权重 - 学习率 × 梯度
```

假设某个权重为 1.0，当前梯度为 0.2：

| 学习率 | 按上述简化公式更新后的权重 |
|---|---|
| 0.001 | 0.9998 |
| 0.1 | 0.98 |

梯度为负时，权重也可以增加。上面的公式对应不带动量和权重衰减的基本 SGD；本课沿用 Adam，它还利用梯度的历史统计量，实际更新不能直接按这张表计算。

学习率过小时，有限轮数内可能进步缓慢；过大时，可能越过合适的参数区域，造成 loss 波动或训练效果差。它不是越大越好，也不是越小越好。

本课比较 `0.0001`、`0.001` 和 `0.1`。其中 `0.1` 是为了观察过大步幅可能带来的问题，不是建议的默认值。具体效果以这次实测为准。

## 3. batch size：分成多少批，就更新多少次

本课为了较快完成对比，从官方训练集随机取出 12000 张用于训练。
默认保留最后一个不足整批的 batch，即 `drop_last=False`。

```text
每轮更新次数 = 向上取整(训练样本数 ÷ batch size)
总更新次数 = 每轮更新次数 × epoch 数
```

| batch size | 12000 张分成几批 | 最后一批张数 | 3 轮更新次数 |
|---|---|---|---|
| 32 | 375 | 32（整批） | 1125 |
| 64 | 188 | 32 | 564 |
| 128 | 94 | 96 | 282 |

例如 `12000 = 187×64 + 32`，所以是 188 批，而不是 187 批。

较大的 batch 通常需要更多显存。在相同样本数和 epoch 下，它会减少参数更新次数；每次更新的梯度也来自更多样本。训练速度和识别效果还与设备、模型、学习率等有关，不能只凭 batch 大小判断。

这里比较的是“每组都把同一批训练图片看 3 遍”，不是“每组更新相同次数”。第二课使用全部 60000 张训练图片，不能把第二课的批次数直接套过来。

## 4. epoch：同一训练集完整学习几遍

以基准组为例，一轮是 188 次更新，三轮是 564 次更新。

脚本在每一轮结束后记录验证结果，所以基准组第 1、2、3 轮的记录就展示了训练轮数增加时的变化；不需要为每个轮数重新启动一个实验。

训练轮数增加不保证验证效果始终变好。如果训练 loss 持续下降，验证 loss 却连续上升，就需要考虑过拟合；一个孤立的波动还不足以下结论。第四课会继续学习这个问题。

## 5. 为什么这次增加验证集

第二课提前确定轮数，训练结束后评估一次官方测试集。本课需要反复比较设置，因此从官方的 60000 张训练图片里划分出：

| 用途 | 张数 | 如何使用 |
|---|---|---|
| 本课训练集 | 12000 | 计算梯度并更新权重 |
| 本课验证集 | 3000 | 每轮评分，帮助比较设置，不更新权重 |
| 本次未使用的训练图片 | 45000 | 缩短入门实验运行时间 |
| 官方测试集 | 10000 | 本课不读取，留作设置确定后的最终评估 |

前三部分由 `random_split` 一次随机划分，互不重叠，所有实验复用同一份划分。
验证集不参与反向传播，但会影响我们的调参选择，因此验证成绩不等于最终测试成绩。

## 6. 运行实验

在项目根目录的 PowerShell 中，先运行基准组：

```powershell
.\.venv\Scripts\python.exe -X utf8 .\day_start\startcnn03.py --experiment baseline
```

再运行全部五组：

```powershell
.\.venv\Scripts\python.exe -X utf8 .\day_start\startcnn03.py
```

也可以在 PyCharm 中直接运行 `startcnn03.py`，默认执行全部五组。使用现有 `.venv`，不需要新增依赖；MNIST 已存在时直接复用，缺失时下载。

| 实验名称 | 学习率 | batch size | 与基准组相比改变了什么 |
|---|---|---|---|
| `baseline` | 0.001 | 64 | 基准组 |
| `lr_small` | 0.0001 | 64 | 学习率缩小到十分之一 |
| `lr_large` | 0.1 | 64 | 学习率放大到一百倍 |
| `batch_small` | 0.001 | 32 | batch size 减半 |
| `batch_large` | 0.001 | 128 | batch size 加倍 |

默认每组 3 轮。每组都重设模型初始化种子，创建新模型和新优化器，并使用单独重设的 DataLoader 随机数生成器。这样模型起点相同，每轮样本排列一致，batch size 不同时只是分批边界变化。不同设备、软件版本或部分 GPU 算法仍可能产生数值差异。

建议阅读顺序：`EXPERIMENTS → main() → create_subsets() → run_experiment()`。
`SmallCNN` 来自第一课，`train_one_epoch` 和 `evaluate` 来自第二课。第二课函数名虽然用于测试，但同样可以对验证集评分。

每次运行在 `output/cnn_lesson03/时间戳/` 保存：

- `metrics.json`：设置、设备、逐轮训练与验证指标、更新次数及各组训练和验证耗时。
- `history.csv`：一行对应一组的一轮，准确率以 0～1 的小数保存。

本课只保存实验记录。各组耗时包含训练、验证和日志输出，适合粗略参考，不是严格的设备性能测试。

## 7. 先看哪几个结果

1. 对比 `baseline` 与 `lr_small`：同样 3 轮，学习率小的一组学到什么程度？
2. 对比 `baseline` 与 `lr_large`：学习率放大 100 倍，验证 loss 和准确率发生了什么？
3. 对比三个 batch 设置：除了验证准确率，也看总更新次数。
4. 单独查看基准组第 1、2、3 轮：验证 loss 和准确率怎样变化？

训练指标是在权重不断变化的过程中累计的；验证指标使用轮末固定的模型计算。不能仅凭二者的大小关系就断言模型有问题。

每组只运行了一个固定种子。本课用它理解现象，不能据此宣布某个设置在所有任务上最好；更严格的比较需要多种随机种子和相应的统计汇总。

### 本机实测记录（2026-10-27）

在 NVIDIA GeForce GTX 1650 上完成了默认五组实验。训练 12000 张、验证 3000 张，每组 3 轮，种子为 42。

| 实验 | 学习率 | batch size | 总更新次数 | 第 3 轮验证 loss | 第 3 轮验证准确率 |
|---|---|---|---|---|---|
| 基准组 | 0.001 | 64 | 564 | 0.1647 | 95.17% |
| 小学习率 | 0.0001 | 64 | 564 | 0.6138 | 84.10% |
| 大学习率 | 0.1 | 64 | 564 | 0.4879 | 85.47% |
| 小 batch | 0.001 | 32 | 1125 | 0.1272 | 96.47% |
| 大 batch | 0.001 | 128 | 282 | 0.2199 | 93.33% |

先从本次结果读出三个现象：

- 学习率缩小到十分之一后，3 轮内的验证效果较差；这不代表增加轮数后仍然一定较差。
- 学习率放大到一百倍也没有带来更好的结果。大步幅组的验证准确率从第 2 轮的 86.73% 降到第 3 轮的 85.47%，验证 loss 从 0.4475 升到 0.4879；这一次波动本身不能单独证明过拟合或确定具体原因。
- 小 batch 这次分数最高，同时它做了更多次参数更新。这个结果不能推出所有任务都应该使用 batch size 32。

基准组随 epoch 增加的记录：

| epoch | 累计更新次数 | 训练过程平均 loss | 轮末验证 loss | 轮末验证准确率 |
|---|---|---|---|---|
| 1 | 188 | 0.8581 | 0.3098 | 91.33% |
| 2 | 376 | 0.2532 | 0.2130 | 93.57% |
| 3 | 564 | 0.1866 | 0.1647 | 95.17% |

这 3 轮里验证效果持续改善，尚不能判断继续增加多少轮会更好。

## 8. 动手练习

1. 本课有 12000 张训练图片。设置 `batch_size=100`、训练 4 轮，一共执行多少次 `optimizer.step()`？
2. 相同 3 轮，把 batch size 从 64 改为 128，参数更新次数是增加还是减少？减少到多少次？
3. 先预测，再把基准组训练轮数增加到 6，观察后 3 轮是否一直进步：

```powershell
.\.venv\Scripts\python.exe -X utf8 .\day_start\startcnn03.py --experiment baseline --epochs 6
```

这条命令会重新从随机初始化训练 6 轮，不会读取之前的模型继续训练。
