# CNN 第四课：过拟合、验证集、数据增强和正则化

第三课学会了改变学习率、batch size 和 epoch。本课接着问：训练集成绩越来越好，是否说明模型越来越好？

目标：能对照训练和验证曲线判断问题，知道数据增强、Dropout、权重衰减分别改变了什么，并按验证结果选择模型。

## 1. 先理解过拟合

训练集用于学习参数。我们真正希望模型能够识别没有参加参数更新的新图片，这种能力叫**泛化能力**。

过拟合可以理解为：模型越来越适应这批训练图片的具体细节，而这些变化没有改善、甚至损害了它对新图片的识别效果。

| 观察到的现象 | 可以怎样理解 |
|---|---|
| 训练和验证 loss 都还较高 | 可能尚未学好，还要检查轮数、模型、数据和优化设置 |
| 训练和验证 loss 都在下降 | 当前训练通常仍有帮助 |
| 训练 loss 继续下降，验证 loss 在多轮里反而变差 | 是过拟合的一个重要信号 |
| 训练准确率高，验证准确率明显低 | 出现泛化差距；还需结合曲线、数据分布和评估方式判断 |

训练准确率达到 100% 本身并不能证明过拟合。验证 loss 的一次上升也不能单独作为结论，要看一段时间的趋势。

## 2. 为什么要重新评估训练集

前两课的训练指标是在一边更新权重、一边预测的过程中累计的。本课又加入增强和 Dropout，训练图片与网络行为都会更加随机。

因此每轮保存三组不同的指标：

| 记录名称 | 图片与模型状态 | 用途 |
|---|---|---|
| `train_online` | 训练过程中的图片，使用 train 模式，权重持续更新 | 了解优化过程 |
| `train_eval` | 原始训练图片，使用轮末固定模型和 eval 模式 | 与验证集做更直接的比较 |
| `validation` | 原始验证图片，使用同一个轮末模型和 eval 模式 | 比较设置、选择轮次 |

图中的两条线使用 `train_eval` 和 `validation`。这两次评分都调用 `evaluate()`，不计算梯度，不更新权重。

不能拿“开启 Dropout、做了随机增强时的训练 loss”直接与“关闭 Dropout、使用原图的验证 loss”比较，然后只凭大小关系判断过拟合。

## 3. 数据集各自负责什么

本课从 MNIST 官方训练集的 60000 张图片中，固定划分出 1000 张训练、3000 张验证，其余 56000 张暂时不用。小训练集能较快展示模型对训练图片和未见图片的表现差距。

| 数据 | 更新模型权重 | 用于选择设置和轮次 |
|---|---|---|
| 训练集 | 是 | 主要用于学习参数和观察训练状态 |
| 验证集 | 否 | 是 |
| 官方测试集 | 否 | 本课不读取，留到设置确定后评估 |

每组都从相同初始权重开始，使用相同训练/验证索引、batch size、学习率和样本排列。验证索引排在固定随机排列的前 3000 项，因此以后用 `--train-samples` 增加训练样本时，验证集也不会改变。

本课的数据划分与第三课不同，不能把两课的准确率当成严格对照。单个固定种子的结果也不能代表所有运行；更严格的结论需要重复实验。

## 4. 数据增强：让同一张图出现合理的变化

本课的训练增强：

```python
transforms.Compose([
    transforms.RandomAffine(degrees=10, translate=(0.08, 0.08), fill=0),
    transforms.ToTensor(),
])
```

- 随机旋转范围为 -10°～+10°。
- 横向、纵向的最大平移比例都是相应尺寸的 8%。
- 图片移出原位置后产生的空白区域填 0，即黑色。

这些变化旨在保留数字含义，让模型见到一些位置和角度的变化。标签不变；仍然只有 1000 个训练样本，只是每次取样时可能产生不同的图像。

变换不能随意加强。手写数字不适合直接照搬自然图片中的所有增强方式，例如把图片上下翻转或旋转 180°，可能改变数字含义或产生不合理的字形。

**随机增强仅用于训练。** 本课建立两个不同的 MNIST Dataset 实例：一个只做 `ToTensor()`，另一个做随机增强。它们使用相同的训练索引；验证集始终使用原图实例。

原因是 `Subset` 只是引用底层 Dataset。如果两个子集共用同一个 Dataset，然后修改它的 `transform`，训练和验证可能一起受到影响。

## 5. Dropout：训练时随机暂时关闭一些特征

在第一课网络的 Flatten 和最后的 Linear 之间插入：

```python
nn.Dropout(p=0.5)
```

训练时，每个输入元素以 50% 的概率被置零；它不是每次精确删除一半，也不是删除模型权重。保留下来的值会乘以 `1 / (1 - p)`，在这里是 2。

```python
layer = nn.Dropout(p=0.5)
x = torch.ones(10)

layer.train()
print(layer(x))  # 由 0 和 2 组成，具体位置随机

layer.eval()
print(layer(x))  # 仍然是 10 个 1
```

它让分类器在训练时不能总依赖某几个固定特征，但丢弃过多也可能妨碍学习。

本课中 `model.train()` 和 `model.eval()` 开始实际影响前向计算：

| 操作 | Dropout 是否生效 | 是否记录梯度 |
|---|---|---|
| `model.train()`，正常计算 | 生效（p > 0 时） | 通常记录 |
| `model.eval()`，正常计算 | 关闭 | 仍可能记录 |
| `model.train()` 配合 `torch.no_grad()` | 仍生效 | 不记录 |
| `model.eval()` 配合 `torch.no_grad()` | 关闭 | 不记录 |

`eval()` 和 `no_grad()` 管的是两件不同的事。

## 6. 权重衰减：对权重施加收缩

本课所有组都使用 AdamW，只在权重衰减组开启：

```python
optimizer = torch.optim.AdamW(
    model.parameters(), lr=0.001, weight_decay=0.1,
)
```

AdamW 在基于梯度的更新之外，对参数施加与参数自身大小相关的收缩。这是一种限制模型过度适应训练数据的方式，不是把学习率变小。

本课为便于理解，对传入优化器的全部参数应用这一设置。其他组显式写 `weight_decay=0.0`，避免 AdamW 的默认衰减混进对照实验。

AdamW 的权重衰减与“把 L2 惩罚直接加到 Adam 的 loss 里”不能简单画等号。本课报告的 loss 都是分类交叉熵，不额外添加一个 L2 loss 项。

`0.1` 是本次实验的一个比较值，不是通用最佳值。增强、Dropout、权重衰减都可能改善泛化，也可能强度不合适、造成欠拟合；要看验证结果。

## 7. 最佳轮次与提前停止

本课使用**验证 loss 最小**作为保存模型的依据。因此，所选轮次不一定是验证准确率最高的轮次。

每当验证 loss 刷新最低值时，复制当时的模型参数。训练完成后，将它保存为对应实验的 `*_best.pth`。这些文件包含模型权重，不含优化器状态；下一课会学习加载和推理。

默认仍然运行完整 30 轮，以便观察后续曲线，保存最佳权重和提前停止是两回事。

可选的提前停止：`--patience 5` 表示连续 5 轮没有刷新最低验证 loss 就停止。它不是“验证 loss 比上一轮高 5 次”；只要没低于历史最低值，就算一轮未改善。达到最大轮数时也会结束。

提前停止只是一种根据验证信号结束训练的规则。它不能保证找到全局最优，也不保证每次都优于完整训练。

### 本机实测记录（2026-10-27）

在 NVIDIA GeForce GTX 1650 上完成了默认四组实验，每组训练 30 轮。四组训练和逐轮评分合计约 89.8 秒，不含数据准备和绘图。

以下“训练准确率”均指轮末对原图重新评分的结果，不是训练过程累计值。

| 实验 | 第 30 轮训练准确率 | 第 30 轮验证准确率 | 所选轮次 | 所选轮验证 loss | 所选轮验证准确率 |
|---|---|---|---|---|---|
| 基准组 | 98.60% | 90.57% | 23 | 0.3546 | 90.53% |
| 数据增强 | 95.40% | 93.77% | 30 | 0.2252 | 93.77% |
| Dropout | 97.50% | 91.00% | 27 | 0.2989 | 91.53% |
| 权重衰减 | 98.50% | 90.47% | 23 | 0.3509 | 90.57% |

这次数据增强组的训练准确率较低，验证准确率却更高。它展示了为什么我们不能只追求训练集分数。
Dropout 这次也改善了验证表现。权重衰减的变化较小，最后一轮准确率还略低于基准，不能说每一种正则化设置都会明显提高分数。

再单看基准组后期：

| epoch | 原图训练 loss | 验证 loss | 验证准确率 |
|---|---|---|---|
| 23 | 0.0941 | 0.3546 | 90.53% |
| 25 | 0.0812 | 0.3599 | 90.77% |
| 30 | 0.0635 | 0.3774 | 90.57% |

第 23 轮之后，训练 loss 总体继续降低，但接下来的 7 轮验证 loss 都未超过第 23 轮的表现，最后还升到了 0.3774。这是在本次记录里值得注意的过拟合迹象，不能通过继续降低训练 loss 来证明模型变好了。

第 25 轮的验证准确率比第 23 轮高，为什么仍保存第 23 轮？因为本课提前规定了按验证 loss 选择。准确率只看选出的类别是否正确，交叉熵还受正确类别的预测概率影响，因此两者不一定同步变化。

单独运行 `--experiment baseline --epochs 60 --patience 5` 时，本机在第 **28** 轮停止，保存的是第 **23** 轮的权重。停止轮次和所选轮次不是同一个概念。这是重新训练的另一轮实验，部分 GPU 计算可使数值略有差别。

## 9. 动手练习

1. 为什么数据增强只加在训练集，验证集保持固定？
2. `model.eval()` 会不会自动关闭梯度记录？只使用 `torch.no_grad()` 会不会关闭 Dropout？
3. 假设三轮验证 loss 是 0.30、0.24、0.27，而训练 loss 是 0.15、0.10、0.07，按本课规则应保存哪一轮？
4. 查看基准组曲线，再运行带提前停止的版本，对照它实际停止和选中的轮次：

```powershell
.\.venv\Scripts\python.exe -X utf8 .\day_start\startcnn04.py --experiment baseline --epochs 60 --patience 5
```

如果想考察更多训练数据，可以用 `--train-samples 5000`。验证集保持相同，但固定 epoch 下更新次数也会增加，要一并考虑。

<summary>做完前三题后查看答案</summary>

1. 增强用于丰富训练变化；固定的原图验证集便于比较不同轮次与设置，避免每次评分时输入也随机改变。
2. 都不会。eval 控制 Dropout 等层的工作模式；no_grad 控制梯度记录。
3. 第 2 轮，因为验证 loss 最低。第 3 轮训练 loss 更低，不能作为替代验证指标的理由。
